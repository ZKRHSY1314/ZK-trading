# 策略问题诊断与优化方向（2026-06-19）

本记录为 review-only / simulation-only 研究结论。未调用真实交易，未接入券商，未修改生产 `rules.yaml`。

## 已写入候选买卖规则层

本轮把经过推敲的主力 2.6x 规则写入：

- `backend/configs/review_only_buy_sell_rules.yaml`

该文件不是生产规则，当前用途是沙盒回测、人工复核和后续规则晋升评估。

### 买入候选规则

1. `mf26x_pre_markup_cost_zone`
   - 只寻找主力拉升前半段。
   - 横盘均价稳定。
   - 当前价处于成本区上方但不远离成本，默认 `1.00x~1.45x`。
   - 如果已到 `2.30x` 以上，不再当买入机会。

2. `mf26x_breakout_confirmation`
   - 需要均线收复、放量、突破确认。
   - 避免单日暴拉后追高。

### 卖出候选规则

1. `mf26x_staged_take_profit`
   - `2.30x`：进入警戒，不加仓。
   - `2.45x`：测试分卖 25%~35%。
   - `2.60x`：主止盈区，继续分卖 35%~50%。
   - 剩余仓位用跌破 5/10 日线、放量滞涨、长上影、炸板等信号退出。

2. `mf26x_distribution_watch`
   - `2.30x` 以上叠加放量滞涨、长上影、峰后回撤、炸板等，降级为出货风险观察。

## 当前系统问题

### 1. RuleEngine 打分上限不够

当前正式规则里可加分的已实现策略只有：

- `dengzhan_low_position_limit_up`：25 分
- `dengzhan_forced_divergence`：20 分

最大正分只有 `45`，但强候选阈值是 `80`。因此即使没有硬风控拦截，也很难产生正式强候选。

解决方案：

- 不直接降生产阈值。
- 先在沙盒层增加 `mf26x_pre_markup_cost_zone` 和 `mf26x_breakout_confirmation` 的候选分。
- 用 replay / signal backtest 验证后，再考虑是否进入正式规则。

### 2. 历史正式回测仍是 0 笔交易

最新正式历史回测：

- `trade_count=0`
- `rejected_by_risk_count=3055`

这说明当前正式回测仍停在候选筛选阶段，不能用它评估止盈止损规则优劣。

解决方案：

- 先把风险拒绝拆成“硬风控拒绝”和“分数不足未入选”。
- 增加规则诊断输出，避免把候选未成单误读成下单失败。
- 用沙盒信号回测先验证新规则，再进入正式 BacktestEngine。

### 3. 日线成交额缺失，正式可执行回测会被卡住

`daily_bar_cache` 当前：

- 总行数：14406
- `amount` 缺失或为 0：14406
- 覆盖股票：50

而回测执行器需要成交额做流动性约束。如果后续买入规则打通，仍可能因为 `missing_liquidity_amount` 被拒绝成交。

解决方案：

- 优先修复日线缓存的 `amount` 字段。
- 如果数据源确实缺失，可增加明确标记的成交额代理值，但必须在报告里标注 `amount_proxy=true`。
- 正式回测只接受可靠成交额或经过标注的代理成交额。

### 4. 卖出规则与主力操盘周期不匹配

正式 BacktestEngine 当前卖出逻辑是：

- 跌 8% 止损
- 涨 15% 止盈
- 持有 5 天退出

这适合短线信号验证，但不适合“长期横盘 -> 主升 -> 2.6x 出货区”的主力路径。

解决方案：

- 先增加 review-only 退出策略层。
- 沙盒里比较两组退出：
  - 短线固定退出：8% 止损 / 15% 止盈 / 5 天。
  - 主力阶段退出：2.3x 警戒 / 2.45x 分卖 / 2.6x 分卖 / 均线和量价退出。
- 只有样本量足够、回撤可控后，才考虑进入正式回测。

### 5. 高分 2.6x 样本里包含 ST、高波动板块和峰后大回撤

2.6x 扫描证明该范式存在，但也暴露出风险：

- 部分股票峰后回撤超过 40%。
- 含 ST 或特殊处理样本。
- 科创板、创业板波动更大，需要降权或仓位上限。

解决方案：

- ST / 特殊处理：直接降级观察。
- 上市时间短或日线不足 240 根：降级观察。
- 科创板/创业板：模拟仓位上限更低，必须有更强确认。
- 接近 2.6x 后不允许把相似度当买入加分。
