## 截点与来源绑定

正式任务需明确采用已验收的回顾性模式和统一的收盘后截点约定，并在每条记录保留 `strict_pit=false`、`training_eligible=false`、`review_only=true`、实盘禁用。事实的经济日期与证据首次进入本研究的时间是不同字段。

上市、日历、停牌及公司行动的原始历史可得时间尚未证明。若使用结构索引的实际整理时间，只能标为“本次证据整理/观察时间”，不能说它是公告发布日期。停牌的事后复牌公告不能让历史截点预知复牌日。每类上下文都要列出消费/未消费以及时间限制；不可只用一个总 PIT 标志遮盖事实差异。

读取器是来源可信度边界：须验证实际 M2 行与清单，调用冻结的标签模块，再核验其输出和代表记录/阶段前缀/审核/对照之间的绑定。自洽的 JSON 哈希不等于已经完成该来源核对。

## 预期产物与验证

1. 实现无导入、构造时副作用的独立读取模块与聚焦测试。正式任务才允许精确两份候选文件的 SQLite 只读连接；采用只读 URI、禁止写入的连接设置，拒绝任意路径、ATTACH、扩展加载或生产服务回退。合成损坏样本位于新的私有输出目录，不触碰冻结库。
2. 首先输出逐标的、逐日期的开发区间对账与排除清单。把价格、停牌、未上市、预热不足、缺证据和真实异常分别保留，任何数值/键/来源不一致都不能进入标签。
3. 按完整开发日期顺序生成标签，不依据后来收益、阶段终点或最终能否找到对照来挑选起点。保存所有候选、非候选、模糊、失败和排除结果及逐级数量；使用冻结策略重建阶段与控制池。
4. 匹配按已验收的同日、流动性档、市场状态、证券池、模式和版本规则运行，保留完整控制记录和未匹配原因，不以重复日期充当不同阶段。
5. 输出先保持待审核。Claude 的程序生成不能自动增加“独立审核”计数；后续 Claude 实际逐案例阅读与 Codex 独立阅读必须各自留下案例/阶段前缀/对照/执行/版本证据。两个 agent 名字不能冒充两次审核执行，也不能标成人工审核。
6. 若少于 50 个正例阶段及每例 3–5 个匹配对照，用完整开发池的逐级排除清单证明限制，不通过调阈值、扩证券池、读取留出期或伪造审核补足。
7. 保存全部生成参数、冻结来源和代码哈希、实际命令和运行结果；复算具有确定性。新输出必须隔离且拒绝覆盖旧目录。正式验收同时复核 M2、旧跟踪文件与生产状态未变。
