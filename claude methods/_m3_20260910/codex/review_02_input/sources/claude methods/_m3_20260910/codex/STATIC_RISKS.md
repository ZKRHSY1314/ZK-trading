# M3 Codex static findings before labels/case extraction

Status: review input, 2026-09-10. This is not a new label policy or a case result. The module owner is Claude under M3-01; Codex has not changed those owned files or consumed real price tables to choose labels.

1. `backend/app/learning/phase_replay.py:33-39` constructs default AkshareProvider and SQLiteStore then initializes the configured store. `create_replay` can persist and its daily loader can fall back to network sources. Reusing the service constructor in an M3 offline script would violate current isolation. New code should consume caller-provided validated inputs without service imports.
2. `_prepare_bars` uses `date.today()` to choose a lookback; repeated historical invocations at later wall-clock dates can select different inputs. A declared cutoff and window must replace this mechanism in the separate M3 namespace.
3. `_label_phases` adds a symbol-specific retrospective user conclusion for SZ002081 after `distribution_seen`. No cutoff-visible review provenance is attached. This cannot become a general M3 label definition or count as independent review. `CORE_REPLAY_TARGETS` calls SZ002115 a success; the text is legacy context, not a current verified label.
4. Existing phase calculations use shortened rolling min_periods and permit missing long-horizon returns in accumulation/test-pull conditions. M3 must explicitly distinguish insufficient observations from a tested low return, define comparisons and precedence, and preserve indeterminate states. The old semantics are not modified here.
5. `OutcomeLabelingService` initializes SQLite and writes outcomes. Its next-session future return computation can be a later-known outcome, but must not feed a cutoff-time candidate, phase or control matcher. Historical decision labels and later outcome availability are separate.
6. The frozen M2 manifest does not contain SZ002115 or SZ002081. It is a data-quality-selected pilot, not a representative market sample or previously reviewed positive/negative library. Repeated daily triggers are not independent episodes. A later case manifest must disclose the sample selection and control/episode dependencies.
7. M2 mode `none` establishes raw unadjusted levels, not corporate-action-neutral returns. Nine known control cash-event documents cannot prove all securities action-free; smooth prices do not prove no corporate action. An event-uncertain window must remain qualified/indeterminate for sensitive labels. Binary32 amount representation and one BJ total-scope interpretation remain provenance limitations.
8. M2 source captures occurred later than their historical bars (`strict_pit=false`). Appending a fabricated close-time availability to every record would hide that limitation. Retrospective computational truncation can be tested independently of historical source availability, with strict-PIT and supervised-readiness fields kept false unless separately supported.
