# M3 逐案例复核约定（读取任务前的准备）

此文只规定 Codex 要检查什么，不采用当前未通过验收的标签策略，不授权新采集，也不改变 M3 的原始目标。具体字段与规则以之后验收并冻结的策略和案例格式为准。

## 一条可计数正例需要什么

逐条评估案例核心及其证据，而不是只查看汇总标签或测试通过数。记录应能回答：

- **何时知道**：股票、阶段、当次选股资格以及最早满足持续时间的决策截点分别是什么；没有用事后终点补写起点结论。
- **用什么知道**：股票与基准实际消费的价格/日期范围、日历和上下文事实有可核对引用；不可得、缺失、停牌、上市深度、公司行动完整性分别说明。
- **为什么符合**：按冻结规则逐项解释主要判断及阈值附近的情况，不用“主力吸筹”等不可观测叙事替代指标证据，不因后续涨跌重新选择起点。
- **哪些证据反对**：保留冲突指标、未来可修订的阶段、短预热和口径限制；给出接受、附条件保留、模糊或拒绝的具体原因。
- **对照是否可比**：三至五只不同的其他股票，决策日期、截点惯例、流动性档和市场状态符合已验收规则；指数、同股多日、重复记录、未知来源或跨切分记录不能补足数量。
- **正例是否独立**：同股区间重叠、相邻片段、链式连接和对照复用须在实际依赖统计中出现。分别报告记录条数、通过逐案复核的正例数、有效依赖组数、唯一对照数与使用次数。
- **谁实际复核了什么**：审阅者身份和类型、执行引用、时间、案例核心哈希、策略和证据版本一起保存；仅填写两个人名或重复调用汇总函数不构成两次审阅。

Codex 和 Claude 的审阅均应准确标为 agent review，不称为人工实审。M3 原始目标中的“至少 50 个独立复核正例、每例三至五个对照”不能由合成案例、重复片段、缺少证据的自动认可或留出区间凑数满足。

## 逐案工作次序

1. 固定待审核心及哈希，检查来源、日期范围、版本、用途与合成/真实标志。先排除无法审阅的记录。
2. 从决策截点允许的证据重算/核对标签依据，然后核对已消费的上下文与日历；记录与案例摘要不一致之处。
3. 同样检查每个对照的非候选结论与配对条件。对照不足时显式记为不足，不能放宽条件补齐。
4. 写独立审阅结论、具体支持与反证、证据引用和限制；审阅结果绑定原核心。任何核心改变都使旧审阅不能沿用。
5. 整理分歧时保留双方原审阅；修订结论须明确取代哪一条及原因。仍无法解释的矛盾进入模糊或待审，不能以最后写入覆盖分歧。
6. 全部完成后再做可计数性、重叠依赖、控制复用和用途审计。审阅进行到一半的记录不能提前算完成。

## 无法达到数量时

先给出可重复的完整开发区间盘点及每级减少的具体原因：可读范围、预热/日历/价格质量、候选阶段、持续时间、对照、实际复核、依赖。保留真实失败和模糊案例。只有这些证据能证明数量限制；某次测试通过、少数例图或尚未执行的筛选不能证明“数据不支持”。不得为了数量调整冻结规则或查看最终留出期选阈值。

M3 完成文档须明确交付能力、测试、可信数据、逐案例证据及运行状态各自的结论，并保留 strict PIT=false、训练/交易效能尚未验证等实际限制。M4 需要另行启动。
