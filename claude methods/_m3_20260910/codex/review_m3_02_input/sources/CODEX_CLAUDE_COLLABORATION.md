# Codex–Claude 智能体协作协议

版本：1.0 · 2026-09-03 · 适用项目：A 股分析、模拟、监控与复盘驾驶舱

## 1. 目标与使用方式

把 Claude 的诊断和方案转成可验证的项目增量，由 Codex 负责本地实现与集成，再通过独立复核收口。协作的事实来源是当前代码、可复现测试和带时间的数据证据，不是聊天中的“已完成”描述。

每次开始先阅读 `AGENTS.md` 和本文件。Claude 的原始建议保留在 `cluade methods/`；它们是待验证的方案输入，不覆盖项目安全规则，也不证明当前代码仍有相同问题。

本文件是协作约定，不是自动调度器。它不会安装或启动 Claude，不会自动向外部模型发送代码、日志或本地数据。用户没有安排 Claude 工作时，Codex 继续独立推进；不得将 Codex 子代理的检查冒称为 Claude 审查。

## 2. 默认职责

| 角色 | 主要职责 | 交付要求 |
| --- | --- | --- |
| 用户 | 确认目标、范围及需要新增权限的操作；验收阶段结果 | 明确下一项任务和不可改变的约束 |
| Codex | 检查本地状态、拆分任务、编写代码、数据源适配、测试与集成 | 最小变更、测试命令和结果、未完成项、回退办法 |
| Claude | 诊断、方案比较、策略逻辑质疑、独立代码/测试审查 | 文件定位、证据、影响、优先级和验收方法；不只给方向性建议 |

这是默认分工，不是能力限制。用户可交换实现者与审查者，但一个任务同一时间只能有一个集成负责人；实现者不得代替审查者声明“独立审查通过”。

## 3. 所有参与者必须遵守的边界

- 实盘交易保持关闭；不新增券商登录、凭据存储、账户/资金读取、真实下单或撤单能力。
- 同花顺在本阶段仅作为市场行情数据源。第三方 skill/MCP 暴露账户工具，不代表项目获得了使用权限。
- 通用屏幕监控只读。模拟点击仅能使用 `AGENTS.md` 已规定的 `/api/sim-cockpit/*` 网关与全部模拟风控门槛；不能借数据接入绕过它。
- 不把“缺字段”当成零或通过，不用模型知识或其他来源冒充本机行情。数据、模型或风控证据不清楚时降级为只读复核。
- 不以提高回测收益为理由放宽安全门槛、回填未来信息或忽略交易成本；零成交不等于策略验证成功。
- 未经明确数据变更任务，不修改本地数据库、历史缓存和知识文件。需要写入时必须先确定范围、备份/恢复办法及校验条件。
- 不输出令牌、账户信息或凭据。交接默认只含必要的代码定位、脱敏摘要和合成测试样本；向外部服务传送原始行情或私有文件必须有相应授权。

## 4. 防止两个智能体覆盖彼此

1. 开始前记录分支、HEAD、`git status --short`，查看涉及文件的现有差异。未提交变更默认属于用户，不重置、不覆盖、不顺手清理。
2. 在任务交接中列明 `write_scope`（允许修改）和 `read_only_scope`。共享目录里同一个文件只有一个写入者；复核者只读。
3. 可并行进行不同文件的实现、只读审查和独立验证；接口、数据库迁移、公共配置由集成负责人协调。
4. 需要隔离时使用独立 worktree；Codex 新分支使用 `codex/` 前缀。worktree 不自动包含当前未提交变更，必须在交接中说明基线和补丁来源。
5. 不运行 `git reset --hard`、`git checkout --`，不全量暂存/提交工作区。任务没有要求时不自动提交或推送。
6. 发现同一文件出现未经交接的新修改，暂停该文件写入并重新核对；不要把冲突解决成“以自己的版本为准”。

## 5. 一项任务的闭环

1. **诊断**：先检查代码与运行状态，区分已复现问题、推测和旧报告结论。
2. **定界**：写清目标、非目标、文件范围、数据影响、安全门槛和可执行验收条件。
3. **实现**：只做当前阶段所需的最小变更，优先复用已有 SQLite、service、API 模式。
4. **自测**：先运行相关测试，再扩大范围；报告实际命令、退出码、通过/失败数量和未运行原因。
5. **独立复核**：审查接口契约、异常路径、未来数据、数据来源、交易禁用和回归风险；有 Claude 实际输出才记录 Claude 审查结果。
6. **收口**：处理阻断项、重新运行受影响测试，记录剩余限制；只有验收条件真实满足才标记完成。

状态约定：`proposed` → `in_progress` → `ready_for_review` → `validated` → `accepted`。其中 `validated` 表示技术验收通过，`accepted` 由用户确认。缺少客户端、权限或关键选择时记录 `blocked` 及恢复条件；代码完成但尚未联通外部依赖时记录 `integration_pending`，不写“接入完成”。

## 6. 交接模板

将下面的模板写在本次任务消息或独立交接文件中；双方只在自己负责的段落补充。无需为了流程创建空数据库或自动任务。

```text
task_id / 标题：
状态 / 负责人 / 复核者：
目标与非目标：
用户授权范围：
基线：分支、HEAD、开始时间、涉及文件的已有未提交变更
write_scope：
read_only_scope：
诊断证据：文件:行号 / 查询口径 / 样本时间与来源
实现摘要与接口变动：
数据影响：无写入，或明确表/时间范围/备份及校验
安全检查：review-only / simulation-only / live-trading-disabled
验收条件：可逐条判定的结果
实测：命令、时间、退出码、通过/失败项
独立审查：实际执行者、发现项、处理状态；未执行则注明
剩余问题、阻塞及恢复条件：
回退办法：仅撤销本任务变更，不覆盖用户已有改动
下一步：一个明确、可执行的动作
```

审查意见格式：`优先级 → 文件:行号 → 触发条件 → 实际影响 → 修复/验收建议`。安全边界和错误数据进入决策链为阻断项；风格偏好不冒充阻断缺陷。

## 7. 同花顺数据源的专项协作约定

- 上游仓库是 `zhuyifang/tonghuasun-agent`；插件旧称 `tonghuasun-codex`，核心 skill 名为 `tonghuasun-agent`。安装时记录仓库地址、固定 commit 和实际安装目录。
- 必须区分四个状态：skill 文件已安装、客户端插件已配置、本机行情调用成功、项目数据源验收通过。这四者不可相互代替。
- 上游当前面向同花顺远航版 `happ.exe`。不能把经典版 `hexin.exe` 当成兼容宿主，也不向未经确认的目录复制 DLL。
- 项目数据入口是 `backend/app/data/tonghuasun_provider.py` 的市场数据白名单，不开放通用账户或交易请求代理。
- 项目仅接受数字 loopback 地址，令牌留在插件管理的本机配置中；不得写入仓库、日志或交接文件。
- 先取少量真实行情样本，核对证券标识、交易日、复权、OHLC、成交额、量额单位与时效，再决定启用 `tonghuasun_first`。不得凭安装成功就切换默认源。
- `GET /api/data/tonghuasun/status` 仅反映配置发现状态，不证明服务存活或行情新鲜。
- 真实样本未通过前保留原数据源策略；测试必须覆盖断连、缺字段、错误证券/复权、非本机地址和令牌泄露风险。
- 初次验收只读、不落库；需要批量补历史数据时另列数据变更范围和校验，不自动全市场回灌。

具体安装结果与恢复步骤记录在 `docs/TONGHUASUN_SETUP.md`；历史库说明见 `docs/MARKET_HISTORY.md`。

## 8. 对 Claude 建议的落地顺序

| 阶段 | 本阶段交付 | 通过标准 |
| --- | --- | --- |
| P0：结果可信 | 缺失基本面、时点可见性、无信号/无成交状态、流动性缺口均可解释 | 相关测试通过；旧回测不伪装成已重跑；区分局部 PIT 与完整历史 PIT |
| P1：行情连通 | 同花顺只读数据接入、真实样本和可追溯来源 | 客户端兼容、样本真实、字段单位已核对、实盘仍关闭 |
| P2：策略与评分闭环 | 澄清同日条件与时序状态机，统一选股、回测、模拟使用的评分口径 | 同输入可复现同结果；样本外与成本检验；不是只看收益数字 |
| P3：稳定模拟运行 | 监控、告警、审计和失败降级 | 缺数据/服务失联时不放行交易；复盘能还原决策依据 |

以上是验收顺序，不是完成声明，也不承诺收益或上线日期。每次只推进证据充分且授权明确的一段。

## 9. 常用验证入口

后端在 `backend` 目录执行已有虚拟环境中的测试，例如：

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_tonghuasun_provider.py tests/test_market_history_refresh_loop.py tests/test_universe_backfill.py
.\.venv\Scripts\python.exe -m pytest -q tests/test_backtest_engine.py tests/test_fundamentals.py tests/test_dengzhan_signals.py
```

前端修改在 `frontend` 目录运行项目 `test` 脚本；以当前 `package.json` 为准。不要编辑 `frontend/dist`。最后检查 `git diff --check`，并核对没有把数据库、数据集、缓存、`.venv`、`node_modules`、构建产物或日志加入 Git。

Codex 指令发现机制参考 [OpenAI 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。本文只规定项目协作流程，不依赖特定模型、API key 或跨产品自动调度。
