## 0. 一页结论

1. **工程基建扎实**：point-in-time 账本、T+1/涨跌停/手续费执行模型、forecast feedback、数据质量门禁、进程身份校验、review-only 不变量、CI 可用。这些是绝大多数个人量化项目没有的。
2. **但它此前不是一个可用的应用**，原因有三：唯一被测量过的信号是反向的（Rank IC −0.17）；回测在结构上不可能成交（39 次运行 0 笔）；至少五条互不相通的选股链路，反馈永远回不到策略。
3. **零成交已修通**（09-03）：同一组 250 只样本，修复前 0 成交，修复后 4 signal → 4 fill → 4 closed。病因是三道串联的门：规则缺市值 → 信号稀有 → **97.6% 的 K 线没有成交额**。
4. **灯盏是稀有事件型策略**：全市场 20 个月只有 145 次 S0，每月 6–7 次。"每日 Top-10 清单"对它不成立，落地形态要改成"稀有事件扫描 + 记分板"。
5. **顺序：先持续运行（review-only 记账）+ 同时回填 2018 年起数据；≥300 笔之前不调任何参数。** 现有策略先改三处结构（出场归位、状态机、中间档位），不加新的交易策略，只加三个对照组。

## 4. 策略问题：先运行还是先优化，改哪里，要不要加

### 4.1 顺序：先运行，再优化——"运行"指 review-only 记账，且与回填并行

- 现在可调参的样本是回测 4 笔、h=1 的 IC 来自 6 个决策日。任何"优化"都是拟合噪声。
- 观察成本接近零：系统本来就是 review-only，ledger 已建好，缺的只是持续跑。运行产生的是**天然样本外**证据。
- 但前向证据很慢：一年 ~80 笔，凑 300 笔要三四年。所以运行不替代回填：前向记账给无偏小样本，2018 年起回填给有偏大样本。
- **今天开始持续运行 + 今晚开始回填 → 两边到位前不动阈值 → ≥300 笔时做一次判断。**

### 4.2 现有策略的三处结构性问题（都不是调参）

1. **出场逻辑不是灯盏的。** 回测引擎把出场硬编码在 `app/backtest/engine.py:117`：跌 8% 止损、涨 15% 止盈、**持有 5 天强平**。规范写的是"跌破 5 日线且跌破涨停均价"、6% 止损、15% 减半仓、持有到分歧。一个"拿到派发"的策略被 5 天强平砍掉，回测出来的任何收益都不是它的。出场应和入场一样进 `rules.yaml`，由策略拥有。**最该先改。**
2. **同根 K 线两条同时命中 → 状态机。** 77 笔 vs 124 笔，且规范本就是先后关系（`IDLE → ARMED → ENTRY_1 → ENTRY_2`）。
3. **中间档位不存在。** watch 与 strong 都需两条同时中，分数要么 100 要么 ≤55.6，观察池永远为空。

参数本身（0.5、50–200 亿、量比 1.5）现在不碰。唯一线索：h=1 唯一正 IC 的特征 `drawdown_from_250d_high`（+0.26）正是灯盏低位规则选的东西——对策略**前提**是弱的正面信号，仅限 1 日尺度、6 天数据。

### 4.3 不加新交易策略，加三个对照组

- 不加：项目的病就是"每次效果不明确就再加一层"，五条链路、2372 行综合分测出 −0.18。
- 加对照：随机 10 只 / 现有综合分取反 / `drawdown_from_250d_high` 单因子。同一 ledger、同一执行模型、同一时段。它们回答"2372 行打分有没有打过一行"。
- 若日后要第二个策略，理由应是**证据积累速度**（中频策略更快告诉你管道靠不靠谱），但那是验证完灯盏之后的事。

### 4.4 判断门

| 时间 | 条件 | 动作 |
|---|---|---|
| 现在 | — | 持续运行 + `akshare_first` 回填 + 出场归位 + 状态机 |
| 回填完成 | 2018 起、≥300 笔、跨 ≥3 个状态 | walk-forward + 三个对照，封存窗只看一次 |
| 判断后 | 有正期望 | 才调参，每次改动先过回放对拍 |
| 判断后 | 没有 | 定位改为"结构化观察 + 记分板"，依然是有价值的应用 |

## 6. 两个 agent 的约定（建议写进 AGENTS.md）

1. 未跟踪文件不算存在：新建模块当天要么 `git add` 进一个 commit，要么删。
2. 改对方当天写的文件前，先看 `claude methods/` 或 commit message 的意图；改完在同一处留一行说明。
3. 严格 point-in-time 是默认；任何近似（投影市值、代理成交额）必须显式开关 + 结果标签，缺一不可。
4. 状态词只能从固定集合取：`completed / partial / no_signal / no_fill / insufficient_data / blocked`，非 completed 必须带 reason。
5. 从 `v1.0` 起：新增子系统必须下线一个同体量旧子系统；新增打分逻辑必须先在封存窗之外证明提升 Rank IC。
