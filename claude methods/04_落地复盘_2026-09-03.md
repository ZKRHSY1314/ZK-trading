# 落地复盘 — 2026-09-03

上一轮（09-01）的结论是"回测在结构上不可能成交"。这一轮把它修通了，并在修的过程中把"为什么"量化到了每一道门。
结论先行：**零成交的病因不是一处，是三道串联的门；现在三道都通了，回测第一次在真实数据上成交。
但同一组测量也说明：灯盏策略是稀有事件型策略，"每日 Top-10"这种产品形态对它不成立。落地要换形态。**

## 一、三道门（全部有实测数字）

同一组样本：跨板块均匀抽 250 只，2025-09-01 → 2026-07-17，52,682 根 K 线。

| 门 | 数字 | 结论 |
|---|---|---|
| **① 规则输入** | 到达市值检查的 16 根 K 线**全部** `unknown`（无市值/PB 数据）| 上轮诊断的根因，成立；但它只挡住了 16 根 |
| **② 信号稀有** | 96.8% 被"不做高位股"挡下；低位 1,667 根里只有 16 根涨停 | 主瓶颈。不是 bug，是策略定义 |
| **③ 执行流动性** | 修好①后 4 个信号 → 4 次尝试 → **4 次全部 `missing_liquidity_amount`** | 缓存里 **97.6% 的 K 线没有 `amount`** |

第③道门是这一轮最大的新发现：

```
source                                   bars      missing amount
tencent.fqkline.qfq                   2,476,100   100.0%
tencent.newfqkline.qfq                   49,727   100.0%
tencent.fqkline.raw+sina...              25,822   100.0%
akshare.stock_zh_a_hist                  62,466     0.0%   ← 只有这 2.4% 有成交额
```

全市场 backfill 走的是腾讯 fqkline，它不给成交额；执行模型没有成交额就拒绝一切买入。
**这意味着在修复前，无论策略是什么，回测在 97.6% 的交易日上都不可能成交。**

## 二、信号到底有多稀有（全市场实测）

`verify/measure_dengzhan_signal_rarity.py`，5,534 只，2024-12 → 2026-07（20 个月）：

| 条件 | 次数 |
|---|---:|
| 低位（≤250日高的 50%）| 50,035（1.91%）|
| 低位 且 涨停 | 318 |
| **S0 = 低位 + 涨停 + 市值 50–200 亿** | **145**（89 只）|
| S0 + 同根 K 线量比≥1.5（rules.yaml 现在的要求）| **77** |
| S0 + 之后 1–5 日内量比≥1.5（规范的状态机）| **124** |
| 其中落在 2026-06 / 07 | **98（67%）** |

三个推论：

1. **全市场每月约 6–7 次入场机会。** 250 只样本 10 个月出 4 笔，和这个频率完全一致。修复是对的，数字就是这么小。
2. **`DENGZHAN_BACKTEST_SPEC.md` 要求 ≥300 笔、跨 ≥3 个市场状态，用现有 2.3 年数据不可能达到。** 需要 2018 年起的数据——而且要有心理准备：样本会高度聚集在熊市底部。
3. **"每天给一份 ≤10 只清单"对这个策略不成立**，绝大多数交易日清单为空。落地形态必须改成
   **稀有事件扫描 + ARMED 窗口跟踪 + 记分板**（见第五节）。

## 五、落地形态：改成什么

### 产品定义（替换上轮的"每日 ≤10 只清单"）

> **一个稀有事件扫描器 + 记分板。**
> 每个交易日 16:30 刷新 K 线；17:00 全市场扫描 S0（低位+涨停+市值带）；命中的进入 5 日 ARMED 窗口，
> 逐日判断情景一/二（回踩不破 / 放量站回）；触发即冻结成一条带止损、失效条件、仓位的建议，写入 forecast ledger；
> 1/3/5/10/20 日后自动标注；**首页第一屏是最近 60 个决策日的累计超额与胜率，不是清单。**
> 大多数交易日扫描结果为空——这是正常状态，界面要把"今天没有信号"当成一个正式结果展示。

### 三件事，按顺序

**1. 刷新 K 线 + 用 akshare_first 重跑 backfill（挂机一晚）**
```powershell
cd D:\codex-A股交易\backend
.\.venv\Scripts\python.exe -X utf8 scripts\backfill_market_universe.py --apply --source-policy akshare_first --days 500
```
一次解决三件事：K 线追到今天、`amount` 从 2.4% 覆盖变成 100%、h=5/10/20 的 outcome 自动补齐。
之后 `execution.py` 的代理路径自然退化为极少数兜底，`liquidity_basis_counts` 会显示出来。

**2. 把 rules.yaml 的"同根 K 线两条同时命中"改成状态机**
现在 `tier_reachability()` 已经把问题打印在启动日志里：strong 和 watch 都需要
`dengzhan_low_position_limit_up + dengzhan_forced_divergence` 同时成立。规范写的是先后关系。
按 `DENGZHAN_BACKTEST_SPEC.md` 的 `IDLE → ARMED → ENTRY_1 → ENTRY_2` 实现——全市场 20 个月是 77 笔 vs 124 笔的差别。

**3. 数据补到 2018，然后按规范做 walk-forward**
不做这步，前两步的结果依然是"n 太小"。做了这步，才第一次能回答"灯盏有没有正期望"。
同时跑三个基线（随机 / 反向 / 单因子 `drawdown_from_250d_high`），否则没有参照。

### 明确不做的

- 不再新增任何选股链路、worker、审批面板。
- 不在拿到 ≥300 笔之前调任何阈值。
- 不把 n=4 的 −0.8% 写进任何报告当作结论。

## 六、两个 agent 的约定（建议写进 AGENTS.md）

1. 未跟踪文件不算存在：任何一方新建的模块，当天要么 `git add` 进一个 commit，要么删。
2. 改对方当天写的文件前，先看 `claude methods/` 或 commit message 里的意图；改完在同一处留一行说明。
3. 严格 point-in-time 是默认；任何近似（投影市值、代理成交额）必须是显式开关 + 结果标签，二者缺一不可。
4. 状态词只能从固定集合里取：`completed / partial / no_signal / no_fill / insufficient_data / blocked`，
   每个非 completed 状态必须带 reason。
