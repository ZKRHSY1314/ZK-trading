## Semantics stated explicitly for Codex

* **Kernel-rejected attempts are not committed.** Delivery 01 registered them (attempt identity, order, sequence). Codex's atomicity expectation (`replay != skipped_duplicate`, economic state unchanged) is met by treating a kernel rejection like a ledger rejection: nothing happened, nothing is consumed, the audit record keeps the kernel reasons and `committed=false`. `unfilled` results are committed (the attempt happened; liveness follows the kernel).
* **Order liveness vs. expiry.** `live=false` is set only from committed results; expiry is not tracked by the ledger clock but enforced by the frozen kernel on every attempt from the bound original terms, so an expired order can never fill regardless of the flag.
* **Audit records are append-only.** `snapshot()["records"]` counts audit entries including uncommitted ones; the economic state (everything else in the snapshot) and `state_hash` change only on commits.
