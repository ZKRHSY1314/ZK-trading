## 2. Events and state

**`AttemptEvent(event_id, sequence, request, expected_result_hash=None, note="")`** — `request` is a kernel `ExecutionRequest` for an already-sized order; `sequence` is a strictly increasing int; `expected_result_hash` optionally pins the kernel result the caller expects.

**`PortfolioLedger(kernel, ledger_id, account_ref, initial_cash, initial_lots=(), expected_policy_hash=None, synthetic=True)`** — `initial_cash` ≥ 0 with two decimals (int/Decimal/decimal string; floats refused); `InitialLot(symbol, quantity, acquired_session, cost, provenance_ref)` declares pre-existing inventory with a declared cost basis.

State (all in `snapshot()`; units explicit): `cash` (CNY, 0.01), `lots[symbol]` in FIFO order by `(acquired_session, created_sequence, lot_id)` with `quantity_original/remaining` (shares), `cost_original/remaining` (CNY), `fees_in_cost`, `fill_price`, `sellable_from_session`, `provenance {kind, event_id, order_id, attempt_id, result_hash, input_hash | provenance_ref}`; `orders[order_id] {symbol, side, decision_id, requested_total, filled_cumulative, remaining, live, terms, terms_hash}`; `capacity[capacity_id] {unit, rate, budget, consumed, evidence}`; `realized_pnl_total`; `state_hash`.

Public surface (tested to be exactly this): `apply(event) -> record`, `account_state(as_of, symbol)`, `positions()`, `settlement_view(session, calendar, sellable_after_sessions)`, `snapshot()`, `reconcile()`, plus read-only properties `records`, `state_hash`, `last_sequence`, `last_applied_executed_at`. All mutable state lives in a private `_state` dict; **every value returned is a detached deep copy** (mutating a returned record, `records` entry or snapshot — including nested lot provenance and capacity evidence — cannot alter stored history, registries or hashes; inputs are never mutated). There is no method that applies a cash or quantity delta without a kernel result the ledger itself produced and re-verified.

## 3. Event record statuses and reasons

| Status | Meaning | Effect on state |
|---|---|---|
| `applied` | kernel `filled`/`partially_filled` | **committed**: cash, lots, orders, capacity, realized PnL, registries, sequence/times, state hash updated in one commit; `effects` lists lot created / sale allocations / capacity consumption / cash before-after |
| `no_effect` (`committed=true`) | kernel `unfilled` | no cash or position effect; the attempt happened: identity, ordering, capacity evidence and order liveness are committed; kernel reasons kept |
| `no_effect` (`committed=false`) | kernel `rejected` | nothing happened and nothing is committed (no registry, capacity, sequence, time or hash change); kernel reasons kept; the event may be corrected and resubmitted |
| `skipped_duplicate` | same `event_id` + payload, or same `(order_id, attempt_id)` + payload already committed | nothing; recorded in order |
| `rejected` | ledger-level refusal (codes below), at any point up to and including kernel-result re-verification | nothing (atomic: all evaluation runs on a working copy that is discarded); only an append-only audit record is appended, so a corrected event may reuse the id |

Ledger reject codes: `invalid_event`, `sequence_not_increasing`, `event_out_of_order`, `duplicate_event_conflict`, `attempt_identity_conflict`, `account_ref_mismatch`, `account_state_mismatch`, `account_state_stale`, `policy_hash_mismatch`, `order_identity_conflict`, `order_terms_conflict`, `order_not_live`, `order_quantity_exceeds_remaining`, `capacity_evidence_conflict`, `capacity_rate_conflict`, `capacity_consumption_mismatch`, `expected_result_hash_mismatch`, `kernel_result_inconsistent`, `invariant_violation`.

Every record carries `payload_hash`, the kernel identities (`result_hash`, `input_hash`, `policy_hash`, `contract_version`, `order_live_after_attempt`, `evidence_grade`), `effective_request` (account derived for the symbol, capacity adapter note), `committed`, `state_hash_before/after`, `state_after {cash, positions, realized_pnl_total}` and `event_record_hash`. `snapshot()["records"]` counts audit entries (including uncommitted ones); the economic state and `state_hash` change only on commits.

## 4. Contracts

**Account state (per symbol).** The frozen kernel's `InventoryLot` is symbol-less, so the ledger never pools symbols: `account_state(as_of, symbol)` returns shared cash plus **only that symbol's** FIFO lots. `request.account` must equal `ledger.account_state(as_of, request.order.symbol)` semantically (cash spelling normalized; inventory aggregated per acquired session; `account_ref`, `synthetic`) and `last_applied_executed_at ≤ as_of ≤ executed_at`; otherwise `account_state_mismatch` / `account_state_stale` / `account_ref_mismatch` before any execution. The kernel always receives the ledger-derived per-symbol state, so T+1, odd-lot and settled-quantity rules are evaluated on the target security alone, and FIFO allocation is symbol-scoped.

**Ordering.** `sequence` strictly increasing; `executed_at` non-decreasing across registered events; a malformed event or a request that fails kernel validation is `invalid_event`.

**Idempotency.** Payload identity = `sha256(canonical kernel record of the request + expected_result_hash)`. Same `event_id` + same payload → skip; same `event_id` + different payload → `duplicate_event_conflict`; same `(order_id, attempt_id)` under another `event_id` → skip if the payload is identical, else `attempt_identity_conflict`. Skips never charge fees or move cash/holdings.

**Orders (immutable terms).** At first committed registration an `order_id` binds its terms: the canonical decision record, `decision_id`, symbol, side, `limit_price`, `submitted_at`, `eligible_from`, `expiry_sessions`, `execution_phase`, the instrument record and the calendar `source_ref` (`terms_hash` in the order view). A later attempt may vary only attempt-time evidence (tradability, price, capacity, attempt, account) and reduce the quantity; any changed bound term is `order_terms_conflict` (with the changed keys listed) — an amendment is a new order identity; symbol/side/decision_id changes are `order_identity_conflict`. `requested_total` is the first registered quantity; later attempts must carry `quantity ≤ remaining` (a reduction is recorded as `remaining_reduced_by_caller`; more is `order_quantity_exceeds_remaining`); after a committed result with `order_live_after_attempt=false` (complete, expired window, final auction) further attempts are `order_not_live`. Expiry itself is enforced by the frozen kernel from the bound original terms on every attempt (`order_expired` → `no_effect`, not committed), so an expired order can never be refilled by re-declaring its eligibility. Cumulative fills never exceed `requested_total`. **Disclosed assumption:** each partial execution is charged by the frozen kernel per attempt, including the per-attempt minimum commission (a 300-share order filled 100 + 200 pays two minimum commissions).

**Capacity (shared resource per `capacity_id`).** A later event with the same `capacity_id` must carry identical evidence fields (`capacity_evidence_conflict`) and the same participation rate (`capacity_rate_conflict`); a new `order_id` never resets the budget. *Share unit:* budget = floor(quantity × rate); the ledger injects `consumed_quantity` = shares consumed so far (the event must carry 0 or that value, else `capacity_consumption_mismatch`) and verifies the kernel's `consumed_after`. *CNY unit — declared adapter:* budget = floor_cents(amount × rate); consumption = the gross amount of each fill at its own price; before each attempt the kernel is handed `quantity = floor_cents((budget − money_consumed) / rate)` with `consumed_quantity = 0`, keeping the original `capacity_id`, `source_ref`, observation instants, kind and basis; the transformation is recorded in `effective_request.capacity_adapter` (`original_amount`, `rate`, `budget_money`, `money_consumed_before`, `remaining_money`, `residual_amount_presented`, `rule`). Consumed money is never re-priced. The frozen kernel was not changed.

**FIFO and fees.** Buy: one lot with `cost = gross + commission + transfer_fee`. Sell: lots consumed FIFO; partial disposal allocates `round_half_up_cents(cost_remaining × matched / quantity_remaining)`; the final disposal of a lot allocates its exact `cost_remaining`, so Σ allocations = original cost to the cent; `realized_pnl = proceeds_net − Σ allocated` with `proceeds_net = gross − commission − transfer_fee − stamp_duty`. Realized PnL, allocations and lot mutations are recorded per sale (`effects.sale.lots`).

**Atomicity.** `apply` deep-copies the state, evaluates everything (validation, kernel execution, result re-verification, effect computation, post-conditions) on the copy and commits once; any failure discards the copy. A ledger rejection or a kernel-rejected attempt therefore preserves cash, lots, capacity budgets, order registry, dedup registries, sequence/times and the state hash exactly, and appends only an audit record.

**Verification of kernel results.** `result_hash` recomputed; `policy_hash` equals the frozen policy; identity equals the request; fee breakdown sums; `gross = fill_price × quantity`; `ledger_entry` deltas equal the fill; a non-fill status carries no effects; `expected_result_hash` (if given) equals the result; the kernel's `cash_after` equals the ledger's cash after the fill and its `capacity.consumed_after` equals the ledger's share consumption. A tampered or inconsistent result — including one correctly re-hashed after alteration — is `kernel_result_inconsistent` / `policy_hash_mismatch` with no effect. Post-conditions (non-negative cash and lots, budgets within limits) raise `invariant_violation` (never observed).

**Reconciliation.** `reconcile()` checks cash = initial + Σ applied `cash_delta`; per-symbol held = initial + Σ applied `quantity_delta`; acquisitions = allocated + remaining cost; realized total = Σ proceeds − Σ allocated; every capacity within budget.

**Determinism.** All arithmetic under the kernel's `ARITHMETIC_CONTEXT` (`localcontext`); the caller's Decimal context and numeric spellings do not change records or hashes. Records are canonical JSON; `state_hash = sha256(previous + canonical state)` on `applied` and `no_effect` events; `event_record_hash` over the record. Inputs are never mutated (`dataclasses.replace` builds the effective request).

**Chronological causality.** Appending later events never changes earlier records or state hashes. The ledger never values positions and refuses no mark input because none exists: valuation, sizing and risk consume the read-only views listed in `LEDGER_POLICY["m4_02b_interface"]`, with marks whose `observed_at ≤` the decision instant they value (M4-02B).

## 5. Limitations (explicit)

* One attempt per event; several orders in one session share capacity only through `capacity_id`; the ledger does not schedule or prioritize attempts.
* Partial buy fills are whole lots (kernel contract); per-attempt minimum commission is charged on every partial execution.
* No mark-to-market, exposure, stop/exit, cooldown, benchmark, delisting, corporate-action or historical logic (M4-02B / M4-03). Initial lots carry a *declared* cost, not a derived one.
* `account_state_stale` requires `as_of ≥ last_applied_executed_at`: two attempts at the same instant must both use that instant as `as_of`.
* Order liveness (`live`) is updated only from committed results; the ledger keeps no clock, so expiry is enforced by the frozen kernel on each attempt from the bound terms.
* Kernel-rejected attempts are not part of the committed history (audit record only); the frozen kernel alone decides whether an attempt happened (`unfilled`, committed) or did not (`rejected`, not committed).
* The ledger trusts the frozen kernel for market rules; it re-verifies arithmetic consistency and identities, not market semantics.
