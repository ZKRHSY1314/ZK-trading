**现状**：39 次回测 0 笔成交，`status` 还返回 `completed`。

**改三处：**

## P0-2　确认 tier 门槛不是数学上不可达

[`backend/app/rules/engine.py:56-70`](../backend/app/rules/engine.py)

正权重合计 45（25+20），`strong_min_score: 80` ⇒ 归一化后需要 raw ≥ 36 ⇒ **只有两条全中才行**。
这等于把"strong"定义成"两条独立信号同一根 K 线同时触发"，而这两条在语义上本来是**先后**关系
（S0 涨停 → 之后 1–5 日出现强制分歧点），不是同时关系。

**改法**：不要动 `strong_min_score`，而是让规则引擎支持**状态机**（见
`DENGZHAN_BACKTEST_SPEC.md` 的 `IDLE → ARMED → ENTRY_1 → ENTRY_2`）。
在状态机落地之前，先加一个断言：

```python
assert self._max_strategy_score() * (tiers["strong_min_score"] / 100.0) <= self._max_strategy_score()
# 并在 __init__ 打日志：达到 strong 需要哪几条规则的哪些组合
```
让"这个配置能不能出 strong"在启动时就可见，而不是跑完 39 次回测才发现。

**验收**：启动时日志出现 `strong tier reachable via: [rule_a+rule_b]`。
